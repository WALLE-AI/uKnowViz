# 内容分析与章节规划

写代码之前先把文章“拆透”。可视化做得好不好，八成取决于这一步：如果说不清每一节读者应该看到什么在动，代码写得再漂亮也只是装饰。

## 1. 阅读时抓五样东西

1. **核心问题**：作者想回答什么？用一个问句写出来（这就是 hero 里的钩子）。
2. **推导链**：从起点到结论的每一步，记成「输入 → 操作 → 输出」。中间的技巧（换元、恒等式、近似、下标平移）都要单独记下来，它们最适合可视化。
3. **关键结论**：最终公式，以及作者对它的**解读**（例如“等价于加了 Short Conv”）。解读往往是最值得做成动画的部分。
4. **实验与证据**：有没有数据？数据是表格里的数字，还是只有文字描述？结论是正面、负面还是持平？
5. **术语**：所有外行不认识的词。

## 3. 规划章节的原则

- **一节一个想法**。标题就是这个想法的结论，比如“单段积分：一段面积如何分给两个端点”。
- **顺着推导链走**，但可以合并琐碎步骤、拆开关键步骤。原文用一句话带过的关键技巧，可能值得单独一节。
- **每节都要有能动的东西**。如果某一步实在没有可动的（纯定义），把它并入相邻章节的公式层。
- **一定要有一个“全景”可视化**：在真实规模的数据上展示最终结论（例如范例 ⑤ 的完整注意力矩阵对比），让读者看到“这些推导合在一起意味着什么”。
- **数值验证贯穿全程**：凡是有闭式解的地方，都在读数里放数值核对。
- **实验章节诚实呈现**：有数字就用真实数字画图并注明出处；只有文字就用 `VIZ.schematic`，并在下方注明依据原文哪句话；连文字都没有就不画。

## 4. 典型文章类型与章节骨架

| 文章类型 | 推荐骨架 |
|---|---|
| 推导型（如本范例） | 问题定义 → 关键技巧（1–2 节）→ 组装出结论 → 全景对比 → 结论解读 → 实验 |
| 新方法 / 新算法 | 基线怎么做、有什么问题 → 新方法的核心改动 → 机制动画（为什么有效）→ 复杂度/成本 → 实验 |
| 性质分析（为什么 X 有效） | 现象 → 简化模型 → 关键量的可视化（随参数变化）→ 推论 → 反例/边界 |
| 优化器 / 训练动力学 | 目标函数地形 → 基线轨迹 → 新方法轨迹 → 超参敏感性 → 实验曲线 |
| 概率 / 生成模型 | 分布直观 → 变换或采样过程动画 → 目标函数 → 与其他方法的关系 |

## 5. 常见陷阱

- **照着原文段落切章节**：原文的段落是为读公式的人写的，可视化要按“哪里需要看图”来切。
- **只画装饰图**：画面变化如果不对应文章里的任何结论，就删掉。
- **公式抄错**：LaTeX 从抓取的 article.md 里复制，不要凭记忆重打；改写成分步形式时，逐步核对等号两边。
- **把作者的推测写成结论**：原文用了“猜测”“也许”，页面也要保留这种语气。
