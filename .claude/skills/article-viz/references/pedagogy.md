# 科普写作指南：🧒 通俗地说

目标读者：**聪明但没学过这个领域的人**，比如理工科本科生、产品经理，或者对 AI 好奇的高中生。他们能跟上逻辑，但不认识术语、看不懂符号。专业读者看公式层，外行读者只看动画和绿色框也能明白大意。两类读者都要照顾到。

## 1. 三层结构，各司其职

| 层 | 读者问的问题 | 写什么 |
|---|---|---|
| 公式层 `.card` | “严格来说是什么？” | 原文公式 + 精确说明 |
| 👀 `.plain.how` | “我该看图里的什么？” | 每种颜色/元素代表什么；先点什么、拖什么、观察什么变化 |
| 🧒 `.plain` | “这到底什么意思？” | 一个比喻 + 用比喻重述本节结论 + 指出图中能验证这一点的现象 |

不要把三层写成同一件事的三遍重复。how 框讲“操作和看点”，plain 框讲“含义和直觉”。

## 2. 好比喻的标准

一个好比喻是**结构同构**的：比喻里的每个角色都对应原概念里的一个角色，比喻里成立的推理，在原问题里也成立。

写之前先在心里列一张对应表，例如：

| 原概念 | 比喻 |
|---|---|
| 相邻两点间的积分面积 | 两村之间的农田 |
| 权重 (1−s) 与 s | 离哪个村近就归哪个村 |
| 指数曲线更高的一端分得更多 | 地势高（肥沃）的一侧收获更多 |

如果某个关键性质在比喻里对应不上，或者比喻会推出错误结论，就换一个比喻，或者明确说出“这个比喻在 X 处不成立”。

**全文最好有一个贯穿始终的主比喻**，在 ⓪ 引入，在后续章节延续（例如“山脉面积”出现在 ①②④）。读者不必每节重新建立心智模型。

## 3. 写法要点

- **先结论，后理由**：第一句就说这一节得到了什么。
- **用具体数字**：“两端一样高时正好对半分”比“权重对称”更好懂。
- **指向画面**：“拖动滑块把中间调高，紫色柱会变矮”，让读者通过亲手操作验证说法。
- **一个框只讲一个想法**：3–6 行；需要列举时用 `<ul>`，最多 4 条。
- **术语首次出现就解释**：用一句不含新术语的话解释，同时收入术语表。
- **说清“为什么重要”**：不只说是什么，还说它带来什么后果（更快？更省？更稳？没用？）。
- **负面结果照实说**：方法没有收益、速度变慢、只在特定条件下成立，都要写，并给出原文的解释或推测（注明是推测）。

## 4. 比喻素材库（按主题，选用前先检查对应表）

| 主题 | 可用比喻 | 注意 |
|---|---|---|
| Attention / Q·K·V | 带着问题查资料：问题(Q) 对标签(K)，取内容(V) | |
| Softmax | 按得分切蛋糕，份额加起来 100%；指数让高分“更贪心” | |
| 温度 / 缩放 | 温度低像“赢家通吃”，温度高像“平均分配” | |
| 积分 / 连续化 | 拍照 vs 全程录像；数柱子 vs 量山脉面积 | |
| 线性插值 | 两站之间用直线“脑补”风景 | |
| 卷积 / 平滑 | 修图的模糊滤镜；每个人和左右邻居商量一下 | |
| 位置编码 / RoPE | 钟表指针：位置越靠后转得越多，比较的是两根指针的夹角 | 夹角只取决于相对距离 |
| 梯度下降 | 蒙眼下山，每步沿最陡的方向走 | |
| 动量 | 滚下山的球有惯性，不会被小坑卡住 | |
| Adam / 自适应学习率 | 每个方向各配一个“步幅调节器” | |
| 归一化（LayerNorm/RMSNorm） | 统一考试换算成标准分 | |
| 正交化 / Muon | 把一堆歪斜的箭头掰成互相垂直、长度一样 | |
| 低秩 / LoRA | 一张大表其实由少数几个“主旋律”叠加出来 | |
| 线性注意力 / RNN 状态 | 边读边记的小笔记本，容量固定 | |
| KV Cache | 已经读过的内容做好书签，不用重读 | |
| 损失函数 | 考试扣分规则 | |
| 正则化 | 给模型的“简洁奖励” | |
| 采样 / 噪声 | 抽签；摇晃的手 | |

## 5. ⓪ 大白话版的写法

1. 1–2 段背景：这个东西是什么，在哪里用，为什么值得关心。可用 `.analogy` 三联卡介绍 2–3 个核心概念。
2. `.plain`：用主比喻讲文章的核心想法（做了什么改动）。
3. `.key`：🎯 一句话结论 + 📉 实验结果（原文没有实验就去掉这行）。
4. 提示读者：后面每节都有绿色框。

## 6. 小结的“三句话讲给朋友听”

第一句讲背景，第二句讲做法和结论，第三句讲价值或局限。三句都不能出现未解释的术语。

## 7. 自检清单

- [ ] 每个比喻都通过了“对应表”检查，没有推出错误结论
- [ ] 每个 plain 框的第一句就是结论
- [ ] 每个 how 框至少包含一个“去拖 X，观察 Y”的具体操作
- [ ] 所有术语都已收入术语表
- [ ] 负面结果、局限、作者推测已照实写出并标注
